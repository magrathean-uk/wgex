# ADR-017 Testing, lab and host safety

Status: Accepted 2026-10-25

**Decision.** Swift Testing (XCTest for UI tests), `go test -race`, a userspace netstack test peer with **receiver-based leak detection** (clear-text marker listeners on the LAN and a dual-homed DNS marker resolver; no host sniffing, no monitor mode), sing-box in Docker, a macOS 27 Tart guest with two snapshots (`clean`, and `approved` after the maintainer approves the daemon once over VNC; `sfltool` cannot approve) for daemon integration, a Lima Linux guest with kernel WireGuard for throughput baselines, and physical devices for NE tests (iPad default; ADR-002). **Host safety is compiled in, not an environment variable:** mutating daemon paths and `SMAppService.register()` require `LabGuard.isLabHost()` = built with `-D WGEX_LAB_BUILD` (only `just lab build`), `sysctl kern.hv_vmm_present == 1`, and a root-owned marker `/var/db/wgex-lab-host` created by the guest provisioning script; the marker file is read-only evidence of a lab host (the former `crashAt`/`allowDevPath` hooks moved to the test-only `WGEXDaemonCoreTesting` library in M1-15; a future crash matrix reintroduces them deliberately); a lint fails on any `EnvironmentVariables` key in a shipped launchd plist. Debug apps never call `register()` on a non-VM host; UI tests and debug windows use `FakeServiceController`. Device tests that enable on-demand, `includeAllNetworks` or full-tunnel routes run only on the designated test device and remove their manager in teardown. The owner's own Mac moves to WGEX only through the cutover runbook (ADR-029).
