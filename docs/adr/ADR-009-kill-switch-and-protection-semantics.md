# ADR-009 Kill switch and protection semantics

Status: Accepted 2026-10-25

**Decision.** Protection states `protected`, `blocked`, `captiveWindow(expires)`, `unprotected`, `unsupported`, `unknown` as before, with these corrections:

**macOS.** Always-on blocking while intended-up and in `connecting`, `reasserting`, `error`; optional **Lockdown** (global, persists across logout, reboot, app quit, daemon restart); **Allow LAN** (default on) is scoped to the underlay interface's own subnet plus link-local and link-scope multicast, never fixed RFC 1918 ranges, and the profile's tunnel ranges are blocked on the underlay before any LAN pass; DNS to non-tunnel resolvers (53 and 853) is blocked ahead of every LAN pass; the daemon's own resolver gets a root-only pass to the underlay's resolvers in blocking states; **Captive window** withdraws routes and the DNS key and opens a narrowed pass (console user, TCP 80/443, DHCP resolvers) for 5 minutes, journalled so a restart closes it. **Lockdown enforces from daemon launch.** Until launchd starts the daemon WGEX blocks nothing, and until the daemon reports its first enforcing status WGEX claims no blocking; the lab does not capture what leaves the Mac in that interval. This early-boot interval is accepted and documented (two lab boots in a macOS 26 virtual machine: about 63 s and about 22 s from kernel boot to the first enforcing status, of which about 59 s and about 18 s passed before launchd started the daemon); v1 adds no earlier boot-time blocker, and the release soak measures the interval on real hardware. The "pass rules persist while the daemon is dead" gap is documented. Mac auto-connect is at login or boot; **no SSID rules on the Mac in v1** (decision; superseded by [ADR-030](ADR-030-on-demand-on-macos.md)). The liveness monitor (ADR-010) keeps the claim honest in every enforcing state.

**iOS/iPadOS.** On-demand `NEOnDemandRuleConnect` with `interfaceTypeMatch = .any` as the baseline (armed on connect, disarmed before manual stop). **Force all traffic** = `includeAllNetworks` on `NEVPNProtocol` (app side), off by default, with explicit `excludeLocalNetworks` and the three other exclusions; consent sheet copy covers the App Store/TestFlight update lockout, CarPlay and Personal Hotspot breakage with local sharing on, local DNS and mDNS breakage with it off, and the real-IP leak during updates; the in-tunnel probe is disabled while it is on. `ProtectionState.blocked` is claimed only for lifecycle states that spike P4-13a measures as blocking; manual stop maps to `unprotected`. Trusted SSIDs can be imitated by a hostile network (documented).

**tvOS.** `enforceRoutes = true` on the protocol, on-demand `.any`, an explicit **Allow LAN** (default on) implemented as excluded routes for LAN prefixes (hardware-verified in P4-14a; if excluded routes lose to `enforceRoutes`, the default flips to `enforceRoutes` off); the UI states "Apple TV cannot enforce a kill switch".

The Mac onboarding no longer offers the automatic transport failover step (`Packages/WGEXUI/Sources/WGEXUI/Screens/Mac/MacPreferences.swift:78`).
