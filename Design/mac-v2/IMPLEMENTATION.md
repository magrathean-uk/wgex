# WGEX Mac v2 implementation comparison

The owner's supplied **WGEX Mac v2.dc.html is the canonical visual handoff**. The v1 HTML and rendered boards are context only. ADR-009 state semantics and the plan's copy rules remain authoritative for claims about protection. This implementation starts from main at `b21b992bf1c88afce2eca9db907036ee1bfaa4c6` and preserves existing public/package signatures. This is a source-to-source comparison; no app or preview was launched to claim visual approval.

## State comparison

All nine existing verdicts compile in both appearances. Protected is green; blocked is orange; captive/unprotected are red; unknown and stale are neutral. v2's connecting/reconnecting checks are neutral in the Mac-specific design presentation; the existing shared presenter and its API are unchanged. The plan's truthful connecting/reasserting consequence lines, unknown reason, stale measurement labels and captive countdown win over abbreviated sample copy. Inactive profiles show neutral Inactive and no active measurements. Quit never stops a backend. The captive action is based on `ProtectionState.blocked` even when the displayed lifecycle is connecting/reasserting/stale.

## Tokens, icon sources and native materials

`Tokens/MacDesign.swift` maps blue/green/orange/red/purple/gray/teal and label levels to semantic system colours. Window/pane/card/fill/separator map to AppKit semantic surfaces, preserving light/dark and Increase Contrast. Native glass, popover, sidebar, selection and button materials adapt to wallpaper and accessibility rather than reproducing CSS alpha values. Native secondary-label alpha failed 4.5:1 on opaque light surfaces. The Mac secondary-label token therefore uses the semantic label hue at 60% opacity; the additional contrast script checks it on both surfaces in all four appearances. No new exact RGB accent is necessary. CSS spacing, radius and type-size constants are retained in the token namespaces; `.body` is the matching 13 pt Mac text style, and nonmatching CSS sizes use SF system fonts at those sizes.

`Apps/WGEXMac/Assets.xcassets` contains the template SVG, both appearance PNGs and a conventional Mac AppIcon source set resized from the light PNG. The asset catalogue is included by the existing source glob and XcodeGen selects the conventional AppIcon set automatically. Bundle inspection confirms the asset compiler sets both icon declarations to AppIcon and packages the compiled catalogue. A generated `Resources/WGEX.icns` is also supplied as a conventional fallback source. No project.yml change was needed. The two PNGs are flattened artwork; they do not contain Icon Composer layers. A future `WGEX.icon` needs an authored layer/background composition and light/dark/tinted variants for a system-selected dark Dock icon and full Liquid Glass icon treatment. Until then the Dock fallback uses the supplied light composition; in-app artwork already switches appearance. No project.yml, package manifest or shared component was edited.

## Verification and limits

94 Mac preview declarations cover menu/main verdicts (including unsupported), all eight Settings tabs, all eight onboarding pages, empty state, toast, import source and five review variants, each light/dark. Previews use deterministic fixtures and fakes only. Compile and test results and lint exceptions were recorded in the project's private phase evidence, which is not part of this repository.

Runtime glass appearance, pixel comparison, keyboard/focus/VoiceOver, Reduce Motion and Increase Contrast interaction have not been inspected. The owner explicitly forbids launching the app here. Real service approval, secure install, persistent secret-store transactions, boot/FileVault, relay management, notifications, updates, diagnostics export and Apple TV transfer remain integrations owned outside this visual task. The existing fake-backend/host-guard boundary is retained. No VM access is required or performed.
